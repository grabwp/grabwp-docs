**Short answer:** this page lists the exact notice and error texts shown by GrabWP in wp-admin, on the **Status** screen, and during signup or login. Match the text you see to find its cause and the troubleshooting guide that fixes it.
**Needs:** Free

## Base (GrabWP Tenancy) notices and errors

| Exact message in UI | Where it appears | Cause in code | Troubleshooting guide |
|---|---|---|---|
| `load.php is not included in wp-config.php.` | Admin notice on every wp-admin page (with link to **View Status**) | `GRABWP_TENANCY_LOADED` is not defined because the `# BEGIN GrabWP Tenancy` block in `wp-config.php` is missing or not reached. | [Notice: load.php is not included in wp-config.php](/help/red-notice-load-php) |
| `Could not find the stop-editing marker in wp-config.php. Please add the line manually.` | Installer / setup check | GrabWP could not find the stop-editing marker in `wp-config.php` to insert the `load.php` block automatically. | [Notice: load.php is not included in wp-config.php](/help/red-notice-load-php) |
| `MU-plugin is not installed. Tenant features may not work.` | Admin notice on GrabWP plugin pages (with link to **View Status**) | `mu-grabwp-tenancy.php` is missing from `wp-content/mu-plugins`. | [Notices about the MU-plugin or data directory](/help/mu-plugin-or-data-directory-notice) |
| `Auto-install of MU-plugin will not work. Manual installation required.` | **Tenancy > Status > Plugin General**, **System Information** (**MU-Plugins Dir Writable** row) | The `wp-content/mu-plugins` folder is not writable by PHP. | [Notices about the MU-plugin or data directory](/help/mu-plugin-or-data-directory-notice) |
| `Data directory is missing.` | Admin notice on wp-admin pages (with link to **View Status**) | The base site data folder (default `wp-content/grabwp-tenancy`) does not exist. | [Notices about the MU-plugin or data directory](/help/mu-plugin-or-data-directory-notice) |
| `Plugin needs write access to create tenant directories and manage configuration files.` | **Tenancy > Status > Plugin General**, **System Information** (**Data Dir Writable** row) | The base site data folder is not writable by PHP. | [Notices about the MU-plugin or data directory](/help/mu-plugin-or-data-directory-notice) |
| `Could not read tenants.php, so nothing was changed. Check the file and its permissions.` | Site create, edit or delete action | `tenants.php` could not be read before saving changes. | [Notices about the MU-plugin or data directory](/help/mu-plugin-or-data-directory-notice) |
| `Root .htaccess needs to be updated for tenant routing.` | Admin notice on GrabWP plugin pages (Apache and LiteSpeed only) | The `# BEGIN GrabWP Tenancy` rewrite block in root `.htaccess` is missing, lacks the current path prefix rules (including a block written before Base 1.1.15), or sits after `# BEGIN WordPress`. | [Path URLs (/site/...) show 404 or a wrong page](/help/path-urls-return-404) |
| `.htaccess files are not used by Nginx. Configure tenant routing in your server block instead.` | **Tenancy > Status > Plugin General**, **System Information** (note under **Web Server**) | The web server is Nginx, which does not read `.htaccess` files. | [Path URLs (/site/...) show 404 or a wrong page](/help/path-urls-return-404) |
| `Path routing requires mod_rewrite. Query string routing (?site=id) will be used as fallback.` | **Tenancy > Status > Plugin General**, **System Information** (**mod_rewrite** row) | Apache `mod_rewrite` is reported as not loaded. | [Path URLs (/site/...) show 404 or a wrong page](/help/path-urls-return-404) |
| `GrabWP Tenancy is not designed for Multisite.` | **Tenancy > Status > Plugin General**, **System Information** (**WordPress Multisite** row shows **Yes**) | WordPress Multisite is active on the main site. | [Hosting requirements](/help/hosting-requirements) |
| `This site still runs as WordPress Multisite. GrabWP needs regular WordPress. Remove every line below.` | **Hosting setup** card (**Multisite and wp-config.php** row) on **Tenancy > Status** and in the setup wizard | Multisite constants in `wp-config.php` still turn Multisite on. | [Settings in wp-config.php that stop GrabWP](/help/hosting-requirements#settings-in-wp-configphp-that-stop-grabwp) |
| `wp-config.php has settings that stop GrabWP. Remove every line below.` | **Hosting setup** card (**Multisite and wp-config.php** row) | `wp-config.php` defines a Multisite, address or cookie constant, or `$base`, that GrabWP sets for each site. | [Settings in wp-config.php that stop GrabWP](/help/hosting-requirements#settings-in-wp-configphp-that-stop-grabwp) |
| `Some of these lines are inside a condition or still used by other code, so GrabWP cannot remove them for you.` | **Hosting setup** card, under **Lines to remove by hand** | At least one listed line is inside an `if` block or its name is still used elsewhere, so **Remove these settings** is not offered. | [Settings in wp-config.php that stop GrabWP](/help/hosting-requirements#settings-in-wp-configphp-that-stop-grabwp) |
| `This is a Multisite network with %d sites. Do not convert it: back up or move those sites first.` | **Hosting setup** card | The main site is a real Multisite network with more than one site. GrabWP refuses to remove its settings. | [Hosting requirements](/help/hosting-requirements) |
| `Your proxy or CDN serves https, but WordPress is not told.` | **Hosting setup** card (**HTTPS behind a proxy** row) | A proxy or CDN reports https, but `wp-config.php` has no HTTPS detection. **Add HTTPS detection** fixes it. | [Hosting setup checks](/help/hosting-requirements#hosting-setup-checks) |
| `Your site works on https, but WordPress still uses http.` | **Hosting setup** card (**Secure address** row) | The site answers on https, but the **WordPress Address** and **Site Address** use http. **Switch to https** fixes it. | [Hosting setup checks](/help/hosting-requirements#hosting-setup-checks) |
| `Tenant admins can install or edit plugin and theme code. That code runs on this server and can read the secret keys every site shares.` | **Tenant file safety** card (**Unsafe**) on **Tenancy > Status** and in the setup wizard | **Disable Install Plugins & Themes** or **Disable Plugin & Theme File Editor** is off globally, forced off in `wp-config.php`, or turned off for one site by a Pro override. | [Tenant file safety warning](/help/client-cannot-install-plugins#tenant-file-safety-warning) |
| `GrabWP lost some of its own code in these files and put it back. Other edits were kept:` | Notice on **Tenancy > Status** | The integrity guard restored a missing or changed GrabWP block in a shared file. | [Install GrabWP](/manage-sites/install#plugin-general) |
| `GrabWP could not put back its own code in these files because they are empty, broken or not writable, so it left them as they are and kept the last good copy in the integrity snapshots folder. Check them now:` | Notice on **Tenancy > Status** | A shared file is empty, truncated, unparseable or not writable. GrabWP never writes a broken file. | [Install GrabWP](/manage-sites/install#plugin-general) |
| `Themes are managed by your host. You can still customize your current theme, menus and widgets from the Appearance menu.` | Client site wp-admin (page title **Themes unavailable**) | **Hide Themes Screen** is on, and the site admin opened the Themes, theme install or theme editor screen. | [Free settings](/manage-sites/free-settings#tenant-capabilities) |
| `You're using a legacy path structure. To comply with WordPress standards:` | **Tenancy > Status** (all tabs) | The site data folder is at an older location (`wp-content/grabwp` or `wp-content/uploads/grabwp-tenancy`). Followed by steps to deactivate, move, and reactivate. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Multiple tenants.php files detected` | **Tenancy > Status** path warning | More than one candidate `tenants.php` file exists on disk; only one is loaded at boot. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Multiple global config.php files detected` | **Tenancy > Status** path warning | Pro `config.php` exists at both new (`wp-content/grabwp-tenancy-pro/config.php`) and legacy (`wp-content/uploads/grabwp-tenancy-pro/config.php`) locations. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Data directory inside uploads/` | **Tenancy > Status** path warning | Active base directory is `wp-content/uploads/grabwp-tenancy`. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Pro config directory inside uploads/` | **Tenancy > Status** path warning | Active Pro config directory is `wp-content/uploads/grabwp-tenancy-pro`. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `SQLite directory inside uploads/` | **Tenancy > Status** path warning | Active SQLite directory is `wp-content/uploads/grabwp-tenancy-sqlite`. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Directory paths hardcoded in wp-config.php` | **Tenancy > Status** info notice | `GRABWP_TENANCY_DIRS_FROM_WPCONFIG` is set because directory constants were defined in `wp-config.php` before `load.php`. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Multiple tenant-aliases.php files detected` | **Tenancy > Status** path warning | More than one `tenant-aliases.php` file exists across candidate directories. | [Where site data lives](/manage-sites/where-site-data-lives) |
| `Invalid or expired admin access token.` | Site auto-login (`wp-login.php?grabwp_token_error=1`) | The `grabwp_token` is older than 1800 seconds (30 minutes) or its HMAC-SHA256 signature does not match. | [Site dashboard icon sends me to the login page](/help/site-login-fails) |
| `Tenant identification failed.` | Site auto-login (`wp-login.php?grabwp_token_error=1`) | The plugin could not resolve a valid site ID on the request. | [Site dashboard icon sends me to the login page](/help/site-login-fails) |
| `No admin user found for tenant access.` | Site auto-login (`wp-login.php?grabwp_token_error=1`) | No administrator account was found in the site's database user table. | [Site dashboard icon sends me to the login page](/help/site-login-fails) |
| `GrabWP cannot read management.php in the GrabWP data folder, so names and tags cannot be saved. Fix or remove the file.` | **Tenancy > Settings > Management** | `{base}/management.php` exists on disk but does not return a valid array. | [Free settings](/manage-sites/free-settings) |
| `The Management setting could not be saved. Check that the GrabWP data folder is writable.` | **Tenancy > Settings > Management** | GrabWP could not acquire `.management.lock` or write `{base}/management.php` when saving the **Show tenant names and tags** toggle. | [Free settings](/manage-sites/free-settings) |
| `Tenant saved, but names and tags could not be written. Check that the GrabWP data folder is writable.` | **Tenancy > Add New** or **Edit Tenant** | The site was saved to `tenants.php`, but writing its **Name** and **Tags** to `{base}/management.php` failed. | [Create and manage sites](/manage-sites/create-and-manage-sites) |
| `Names and tags could not be written. Check that the GrabWP data folder is writable.` / `The tag could not be deleted. Check that the GrabWP data folder is writable.` / `The tags could not be deleted. Check that the GrabWP data folder is writable.` | **Tenant Tags** (`admin.php?page=grabwp-tenancy-tags`) | Adding, updating or deleting a tag could not be written to `{base}/management.php`. | [Create and manage sites](/manage-sites/create-and-manage-sites) |
| `Enter a tag name.` / `The slug can use lowercase letters, numbers and hyphens only.` / `That tag no longer exists.` / `A tag with that slug already exists.` | **Tenant Tags** (`Add New Tag` / `Edit Tag`) | The tag name was empty, the custom slug had characters outside `a-z`, `0-9` and `-`, the edited tag was deleted, or another tag already uses that slug. | [Create and manage sites](/manage-sites/create-and-manage-sites) |

| `Activation mismatch; refusing to clear license.` | **Tenancy > License** | The activation ID passed to clear the license does not match the stored activation ID. | [Pro license messages](/help/pro-license-messages) |
| `Failed to save Pro settings. Please check file permissions.` | **Tenancy > Pro Settings** | GrabWP Pro could not write `config.php` in the Pro configuration folder. | [Backup, restore or "Failed to save Pro settings"](/help/backup-restore-and-save-problems) |
| `The Isolated MySQL password is not available any more.` | Setup wizard / Pro database setup | The stored MySQL password could not be decrypted. | [Database options](/manage-sites/database-options) |
| `Isolated sites start without themes. Install one under Tenants > Plugins & Themes after creating the site.` | **Tenancy > Pro Settings > Isolation** and site create/edit form | Informational advice shown when new sites are configured to get their own themes. | [A site cannot install or find plugins and themes](/help/client-cannot-install-plugins) |
| `symlink() is not available on this server.` | **Tenancy > Pro Settings > Symlink** | The PHP `symlink()` function is disabled on the host. | [Hosting requirements](/help/hosting-requirements) |
| `This backup has no WordPress site data, so nothing was restored. The site is unchanged.` | **Restore Tenant** | The backup's database has no WordPress options table. Since Pro 1.1.18, the restore stops before any table is dropped. | [Backup, restore or "Failed to save Pro settings"](/help/backup-restore-and-save-problems) |
| `The backup database could not be restored. Nothing was changed on the site. Details: %s` | **Restore Tenant** | The database import failed before the site's old tables were removed (for example a connection error). | [Backup, restore or "Failed to save Pro settings"](/help/backup-restore-and-save-problems) |
| `The backup database could not be restored, and the site's old database tables were already removed. Restore another backup to repair the site. Details: %s` | **Restore Tenant** | The database import failed after the old tables were removed. | [Backup, restore or "Failed to save Pro settings"](/help/backup-restore-and-save-problems) |
